## The investigation, not a query tour

Chapter 5 is a single investigation against one stated hypothesis, and the hypothesis does not survive:

> **Working hypothesis.** Publishing is low because users are not engaged enough with the product. If that is true, the investment is engagement.

Publishing is flat while the AI coworker is plainly busy. The chapter asks one question at a time, prints the actual result, and lets that answer choose the next question. The first query already contradicts the hypothesis — the users are engaged — and the sections after it show why the real constraint would have stayed invisible to anyone who stopped at the first number.

Read each query for what it asks, not for syntax to memorise. The fifteen examples move through:

1. `SELECT` and `WHERE` over published documents.
2. Scalar subqueries that count accounts, messages, and documents together.
3. `GROUP BY` for the published/unpublished split.
4. A join whose row count exposes a changed grain.
5. Joins across documents and their attached files.
6. Persona-level aggregation of users and messages.
7. A common table expression that puts one row per user back.
8. Counting the engaged users who never published — the query that kills the hypothesis.
9. `CASE` for explicit analytical categories.
10-12. Common table expressions and subqueries that compare per-user and per-persona behaviour.
13-15. Private drafts, their owners, and the absence checks the schema can still not answer.

The complete runnable file is [chapter_5_examples.sql](../sql/noted/queries/chapter_5_examples.sql), generated from the chapter itself so the printed results and the runnable results cannot drift apart.

## Five-minute walkthrough

1. State the working hypothesis out loud before reading any result.
2. Identify the output grain of each query: one document per row, or one user per row.
3. Watch the grain change at the first join, and say what the row count now means.
4. Explain why engaged-but-never-published is the decisive count.
5. Name the denominator each rate is built on.
6. State what the schema cannot answer, and what signal is simply absent.

## Evidence boundary

A syntactically valid query can still answer the wrong product question. The rows are synthetic: 50 users expanded from a fixed seed by Noted's own seeder, built to hold the patterns this chapter investigates. Every result is therefore reproducible rather than discovered, and none of the figures is a production measurement.
